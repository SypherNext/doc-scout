Consistent Hashing

Consistent hashing is a technique for distributing data across a changing set of servers while minimizing how much data has to move when a server is added or removed. It solves a specific problem with the obvious approach to sharding data: if you distribute keys using something like server_index = hash(key) % number_of_servers, then changing the number of servers changes the result of that formula for almost every key, forcing nearly all data to be reshuffled even if only one server was added.

Consistent hashing avoids this by mapping both servers and keys onto the same fixed circular space, usually visualized as a ring of numbers from zero up to some large maximum value. Each server is hashed to one or more positions on this ring. Each key is also hashed onto the ring, and the key "belongs" to whichever server's position is the first one encountered going clockwise from the key's position. To find which server owns a key, you hash the key and walk clockwise around the ring until you hit a server.

The benefit shows up when the set of servers changes. If a new server is added, it is hashed onto the ring at some position and takes over ownership of only the keys that fall between its position and the previous server's position going clockwise, the range it is now the first to reach. Every other key on the ring is unaffected, because the first server encountered clockwise from those keys has not changed. Removing a server works the same way in reverse: its keys are picked up by whichever server is next clockwise, and no other key moves. In both cases, only a small, predictable fraction of keys needs to move, rather than nearly all of them.

A plain version of this idea has an uneven-distribution problem: with only a few servers placed randomly on the ring, one server might end up owning a much larger arc than another, receiving a disproportionate share of the keys. The standard fix is to give each physical server many positions on the ring, called virtual nodes, rather than just one. A server might be hashed to a hundred or more points scattered around the ring under slightly different labels. Averaged over a hundred small arcs instead of one large one, each server ends up owning a roughly equal total share of the ring, and the system's load balances far more evenly without changing the core algorithm.

Consistent hashing is widely used wherever data needs to be sharded across a pool of servers that can grow or shrink, including distributed caches, distributed databases, and content delivery networks choosing which edge server or origin shard should handle a given piece of content.
